# Hostinger Shared Hosting Deployment Guide

This project is configured for deployment on Hostinger shared hosting using Git + SSH.

---

## 1. What Gets Deployed

This is a **Filament-only** Laravel application. The Filament admin assets are already published to `public/js/filament` and `public/css/filament` and committed to Git, so **no `npm run build` is required** for the admin panel to work.

The default Laravel welcome page has been replaced with a redirect to `/admin`.

---

## 2. Git Ignore Check

The following are already excluded from Git:

- `/vendor`
- `/node_modules`
- `.env`
- `/public/build`
- `/public/hot`
- `/public/storage`
- `/database/database.sqlite`
- `/storage/*.key`

**Never commit `.env` or `vendor/` to Git.**

---

## 3. Recommended Hostinger Folder Structure

Hostinger serves files from `public_html`. For security, place your Laravel application **outside** `public_html` and only expose the `public` folder contents.

### Recommended structure

```
/home/your-username/
├── task-manager/          <-- Laravel application (cloned from Git)
│   ├── app/
│   ├── bootstrap/
│   ├── config/
│   ├── database/
│   ├── public/            <-- DO NOT point domain here directly
│   ├── resources/
│   ├── routes/
│   ├── storage/
│   ├── vendor/            <-- generated by composer install
│   ├── .env               <-- created manually on server
│   └── ...
│
└── public_html/           <-- Hostinger document root
    ├── index.php          <-- custom index.php (see deploy/hostinger-index.php)
    ├── .htaccess          <-- see deploy/hostinger-htaccess
    ├── css/
    ├── js/
    ├── filament/
    ├── favicon.ico
    ├── robots.txt
    └── ...
```

### Steps to set up

1. SSH into Hostinger:

```bash
ssh -p 65002 your-username@your-hostinger-server
```

2. Clone your repository outside `public_html`:

```bash
cd ~
git clone https://github.com/managerhibc-rgb/hostinger-test1.git task-manager
```

3. Copy the `public` folder contents into `public_html`:

```bash
cp -r ~/task-manager/public/* ~/public_html/
```

4. Replace `public_html/index.php` with the custom version that points to your Laravel app:

```bash
cp ~/task-manager/deploy/hostinger-index.php ~/public_html/index.php
cp ~/task-manager/deploy/hostinger-htaccess ~/public_html/.htaccess
```

> Edit `public_html/index.php` and change `$laravelPath` to match your actual Laravel path if needed (default is `__DIR__ . '/../task-manager'`).

---

## 4. Alternative: Run Inside public_html

If you cannot place Laravel outside `public_html`, you can run the entire app inside `public_html/task-manager` and use a root `.htaccess` to redirect traffic to the `public` folder.

**This is less secure** but works if you have no other option.

Example root `.htaccess` for `public_html/`:

```apache
RewriteEngine On
RewriteCond %{REQUEST_URI} !^/task-manager/public/
RewriteRule ^(.*)$ /task-manager/public/$1 [L]
```

Then point your domain to `public_html/task-manager/public` if Hostinger allows changing the document root in the subdomain/advanced settings.

## 5. Server Setup Commands (SSH)

After cloning, run these commands inside `~/task-manager`:

```bash
cd ~/task-manager

# 1. Install PHP dependencies (no dev packages)
composer install --no-dev --optimize-autoloader

# 2. Create .env file from example
cp .env.example .env

# 3. Generate application key
php artisan key:generate

# 4. Set up database (MySQL recommended)
# Update .env with your Hostinger MySQL credentials first, then run:
php artisan migrate --force

# 5. Link storage folder
php artisan storage:link

# 6. Cache config/routes/views for production
php artisan config:cache
php artisan route:cache
php artisan view:cache

# 7. (Optional) Seed demo data
php artisan db:seed --force
```

---

## 6. Database Setup

Hostinger shared hosting uses **MySQL**. Update `.env` with the credentials from your Hostinger control panel:

```env
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=your_database_name
DB_USERNAME=your_database_username
DB_PASSWORD=your_database_password
```

Create the database first in the Hostinger control panel, then run `php artisan migrate --force`.

---

## 7. Is npm Build Required?

**No.** This project is Filament-only and does not require a Vite build for production. The Filament assets are pre-published and committed to `public/`.

However, if you later add custom frontend pages that use Vite, you will need to build locally and either:

1. Commit `public/build/` to Git (remove `/public/build` from `.gitignore`), or
2. Run `npm install && npm run build` on the server if Node.js is available.

For now, the commands are:

```bash
# Not required for this project, but provided for reference:
npm install
npm run build
```

---

## 8. PHP Version

This project requires **PHP 8.2 or higher**. In your Hostinger control panel, set the PHP version for your domain to **8.2+** (preferably 8.3 or 8.4).

---

## 9. Post-Deployment Updates

When you push new code to Git and want to update Hostinger:

```bash
ssh -p 65002 your-username@your-hostinger-server
cd ~/task-manager
git pull origin main
composer install --no-dev --optimize-autoloader
php artisan migrate --force
php artisan config:cache
php artisan route:cache
php artisan view:cache

# If public assets changed, re-copy them:
cp -r ~/task-manager/public/* ~/public_html/
```

## 10. Troubleshooting

| Problem | Solution |
|---------|----------|
| 500 error | Check `storage/logs/laravel.log` |
| File permission issues | Set `storage/` and `bootstrap/cache/` to 755 or 775 |
| CSS/JS not loading | Ensure `public/` contents are copied to `public_html/` |
| Admin panel not accessible | Go to `/admin` directly; Filament login is at `/admin/login` |
| Database errors | Verify `.env` DB credentials and that MySQL database exists |
| Storage links broken | Run `php artisan storage:link` and ensure symlink is inside `public_html` |
